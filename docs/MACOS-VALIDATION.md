## 原生应用生命周期验收

- `python3 tests/macos-lifecycle.py dist/ClaudeGuard.app` 已对最新 Apple Silicon release 包实跑通过。
  脚本拒绝触碰预先运行的同路径实例；先用 LaunchServices `open -n -g` 显式传入
  `CG_SMOKE_STATE=pass` 和独立 `CG_DATA_DIR`，关闭通知、结束进程、更新、自启及守护对象。
- 临时 Swift/AppKit 工具只按本脚本创建的准确 PID 与可执行文件路径查询/退出应用，
  不用可能歧义的 bundle identifier，不申请 Accessibility 或改变系统权限。
- 后台 `--tray` 启动保持 0 个可见主窗口且应用未激活；二次 `--tray` 转交后第二进程退出，
  原 PID 保持且无可见主窗口，未改变应用激活状态。
- 对已有实例执行 `open -g -a` 后仍无可见主窗口、未激活；执行前台 `open -a` 则恢复同一
  进程的单个主窗口，并实际成为活动应用。这覆盖 Finder/Dock 类重新打开事件与后台登录启动
  的区别。修复前曾复现“应用已激活、主窗口仍隐藏”，补接原生 Reopen 与窗口恢复后通过。
- 二次及重复 `--settings` 均保持原 PID、单个主窗口以及活动应用状态。
- `NSRunningApplication.terminate()` 发送正常 Quit，准确测试 PID 退出；无网络或客户端更新恢复
  记录落盘，隔离配置仍保持关闭结束进程/自动更新/自启，待发服务没有启动。
- 另行人工点击红色关闭按钮：进程保持运行且窗口数为零；从 Dock/Finder 重新打开后恢复同一 PID
  和一个窗口。对显示中的窗口执行外部隐藏后再次打开也恢复正常。
- 人工展开并操作设置页主要分组；不包含每个折叠区域逐控件的人工点击矩阵。
