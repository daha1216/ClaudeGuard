# 飞书群通知

飞书通知集成在 ClaudeGuard 设置中，由独立后台线程发送。无需另行运行通知助手。

## 配置

1. 在飞书群内添加自定义机器人，复制 Webhook。
2. 打开 ClaudeGuard 的“设置 → 飞书群通知”，启用通知并填写 Webhook。
3. 若机器人启用了签名校验，填写对应签名密钥；若设置了关键词，请允许 `ClaudeGuard`。
4. 保存后点击“测试通知”，确认群内收到明确标注的测试消息。测试会向实际机器人发送一条消息，不触发熔断。

只接受 `https://open.feishu.cn/open-apis/bot/v2/hook/…` 形式的飞书自定义机器人地址。机器人若配置 IP 白名单，需允许这台电脑直连飞书时使用的出口。

保存后输入框不回显凭据。留空表示保留已有值；要移除签名，使用“清除已保存的签名密钥”选项。Webhook 和签名密钥通过当前 Windows 用户的 DPAPI 加密保存在 `%APPDATA%\ClaudeGuard\feishu.json`，前端及状态查询只获得“是否已配置”。加密文件不作为跨 Windows 用户迁移凭据的方式。

如果发现旧版独立通知助手的兼容配置，守护器会尝试读取并校验；只有当前用户能够解密时才使用。迁移后应退出旧助手并取消其自启，避免两套程序重复推送。

## 发送时机

- 检查由正常转为异常、首次发现异常时通知；同一持续异常不会每轮刷屏。
- 异常进一步触发熔断时单独报告；恢复正常时发送恢复通知。
- 客户端更新准备完成、确认成功、失败或需要处理时，使用同一通知队列。
- 重新启用通知后，仍在持续的异常会重新报告一次。

正常检查不会持续发送“正常”消息。事件正文可能包括出口 IP、异常原因及处理状态，这些内容会发到所配置的群中。

## 成功、重试与补发

入队或完成 HTTP 请求不代表送达。只有 HTTP 成功且飞书响应业务状态为 `0`，才记录发送成功。请求采用直连 HTTPS，不继承被监测的代理，不跟随重定向。

网络错误、限流和暂时服务故障会退避重试，每条通知最多尝试五次；明确拒绝则立即停止自动重试。无法确认回执时，机器人可能已收到消息，因此重试和手动补发都可能重复；消息保留同一事件编号供识别，不承诺恰好送达一次。

待发送队列最多保留 100 条。队列溢出、永久拒绝或尝试耗尽的事件进入失败记录；最近 100 条失败持久保留，更早记录超过上限时计入丢弃数量。后续其他消息发送成功，不会清除先前失败记录。延迟超过一分钟的通知标注延后发送时间。

设置中可查看队列、失败数量、最后错误、下次重试时间及最近成功发送时间。修正机器人关键词、签名或网络问题后，点击“补发失败通知”，在队列容量允许的范围内将失败事件重新排队，保留原事件编号。

配置变更的行为如下：

| 操作 | 待发送队列 | 失败记录 |
| --- | --- | --- |
| 停用通知 | 清空 | 保留，可重新启用后补发 |
| 更换 Webhook 为其他地址 | 清空 | 清空，避免发给新目标 |
| 修改或清除签名 | 清空 | 保留，可修正后补发 |

重复保存相同 Webhook 或相同签名不会清空队列和失败记录。

已经发出的网络请求无法撤回。关闭到托盘后继续发送；完全退出守护器后停止，重新启动时读取已保存队列。

## 状态与隐私

`ClaudeGuard.exe --feishu-status` 可读取无明文凭据的本地状态快照；该命令不会发送测试消息。发送测试和补发操作在运行中的守护器界面进行。

只有 Webhook 和签名密钥使用 DPAPI 加密；持久化事件正文、错误信息和日志不加密。提交故障报告前应检查并脱敏出口 IP、群内信息和其他诊断内容，不要上传凭据或整个个人数据目录。
